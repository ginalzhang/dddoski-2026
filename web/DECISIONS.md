# DECISIONS

Where the spec left room for interpretation, these are the choices made, usually the stricter or simpler option.

## Product and game rules
- **The gate is on the server.** `/api/feed` returns `409` (`QuizOwed` / `StudyHall`) whenever a quiz is owed or Study Hall is unfinished. The client holds at most the current Short plus 2 prefetched IDs. The correct answer index is never sent to the browser.
- **Quizzes are snapshots.** Starting a quiz copies the question, the shuffled options and the correct index into the quiz record. Editing or deactivating a link in admin mid-quiz does not change a quiz already in progress.
- **An answer after `expiresAt` counts as wrong** and sends you to Study Hall, the same as a wrong answer. There is no time-based lockout anywhere.
- **Credits can't be earned while owed.** `/study` can't earn credits while the session is in `quizOwed` or `studyHall`, so you can't farm your way out of a debt. Credits are decremented atomically.
- **Minimum watch rule.** The server checks `watchedSeconds >= max(MIN_WATCH_FRACTION × duration, min(10 s, duration))` (default fraction 0.7). If the duration is unknown, it requires 10 s. The reported watch time is also checked against the wall-clock time since the Short was served, with 2 s of slack.
- **Study Hall escalation** is `min(consecutiveFunFails, MAX_REQUIRED)`. A second wrong answer on a reel moves to a different reel, and that reel is reused only after all others are exhausted. Reels are picked least-recently-seen first, so the app never deadlocks. `STUDY_HALL_ESCAPE` is off by default.
- **Unplayable edu reels** (player error 100/101/150) are marked and skipped. They never count toward `required`.

## Architecture
- **The MVP uses an in-memory store.** It is a singleton on `globalThis`, with optional `.data/store.json` persistence (`STORE_PERSIST=1`). `db/schema.sql` documents the intended Postgres/Supabase schema, but no adapter is wired up yet. State is lost on restart and is not shared across serverless instances. This is stated plainly in the README.
- **Curated mode is the zero-config default.** If `APIFY_TOKEN` or `ANTHROPIC_API_KEY` is missing, the fun feed is served from `seed/fun-links.json`. Each fun link has a hand-written quiz written from its title.
- **Next.js `cacheComponents` is disabled** in `web/`. Every gate route is dynamic and per-session, so we skip the caching layer and leave it off for simplicity and predictability.
- **Educational links never leave the server.** Only fun-feed titles and transcripts go to Apify and Anthropic, and only in generated mode.

## Seed data
- **Real IDs only.** Seed IDs were taken from the channels' actual YouTube Shorts tabs (3Blue1Brown, Numberphile, MindYourDecisions, Andy Math, Veritasium for edu; MrBeast, Dude Perfect, Zach King, Mark Rober for fun). Each was confirmed with oEmbed (HTTP 200 = exists and embeddable) on 2026-10-16.
- **Content mix.** 17 of the 24 edu links are `math`; the other 7 are `science`.
- **Durations are unverified.** They are left `null` because no `YOUTUBE_API_KEY` was available. Shorts are 3 minutes or less by definition, and `seed:verify` fills in the duration when a key is set.
- **Some quizzes need review.** Quizzes that couldn't be checked against the video's actual content are marked `"comment": "quiz written from title; review"`. Every answer is still mathematically or factually correct for the stated topic.
- **Lenient custom lists.** `seed:verify` accepts plain URL strings in the `data/*-links.json` custom lists. It reports problems with them but only rewrites object rows (`--write`).
- **oEmbed is the fallback check.** Without `YOUTUBE_API_KEY`, `seed:verify` uses oEmbed: 401/403 = embedding disabled, 404/400 = gone, anything else = transient failure (still reported as a failure). With a key, it uses Data API `videos.list` and also enforces duration ≤ 180 s and no age restriction.

## Generated fun feed + quiz (merged from .decisions-generated.md)
- Actor input fields verified 2026-10-16 from each actor's `.md` page: streamers `{channels:[name-without-@], maxResultsShorts, sortChannelShortsBy:"NEWEST"}`; makework36 `{searchQueries, maxResultsPerQuery, onlyShortsFilter:true}`; scrapestorm `{hashtagKeywords, contentType:"Shorts", maxItemsPerKeyword}` (its item fields `"Short/Video ID"`/`Title` come from the README example, not a formal schema); devsef `{videoUrls (≤200, bare IDs ok), includeSegments:false}` → items `{videoId,status,text,language,isAutoGenerated}`.
- Apify spend: run-sync-get-dataset-items doesn't report the actual charge, so each attempted run records its `maxTotalChargeUsd` as spend (conservative upper bound). Discovery cap per source `APIFY_DISCOVERY_MAX_USD` (default 0.25); transcripts cap `APIFY_TRANSCRIPT_USD_PER_ID` × ids (default 0.005, min 0.05).
- LLM spend estimated from `usage` at `LLM_USD_PER_MTOK_IN/OUT` (defaults 5/25; set to the real Opus 5.5 rates).
- Spend is kept in memory and keyed by UTC day; it resets when the process restarts. Cap `DAILY_SPEND_CAP_USD` (default 5). Over the cap, generateFunQuiz goes straight to the policy rung, prefetch does nothing, and discovery serves its cache or throws SpendCapError.
- Discovery calls all FUN_SOURCES in parallel (allSettled), interleaves the results round-robin, and dedupes by ID. The cache is in memory with `fetched_at` and a 30 min TTL. On refresh it appends only new IDs, so cursors stay stable. The cursor is an opaque numeric offset and pages have 3 items. A refresh failure while a cache exists still serves the cache. If every source fails, it throws the first ApifyError.
- ApifyError kinds: 402→payment, 408 or 25 s abort→timeout, 401/403→auth, 429→rate_limit, other→error, missing token or sources→config. Transcript items with status `blocked`/`error` are not cached (they get retried later). `no_transcript`/`unavailable` are cached as "none".
- Ladder: store `getCachedTranscript` (TRANSCRIPTS_PATH file, imported lazily; accepts either the VideoRow or the {text,lang,isAutoGenerated} shape) → in-memory/in-flight prefetch → Apify → LLM transcript quiz → LLM metadata quiz (only with `metadata-then-pass` and a known title) → policy. Videos from the custom list need no hand-written quiz: transcript → LLM works.
- `fail-closed` skips the metadata rung and throws QuizPolicyError.
- LLM: each rung gets up to 2 attempts. It retries on refusal, max_tokens, invalid or failed parse, and 429. Any other API status error drops to the next rung, because the SDK already retries it internally.
- QuizSchema leaves out length/min/max constraints because structured-output JSON schema support is limited. `validateQuiz` checks them instead: exactly 4 distinct (case-insensitive) non-empty options, each ≤25 words, no "all/none/both/neither of the above", and correct_index 0-3. Options are shuffled server-side with Fisher-Yates and the correct index is remapped.
- `discoverFunFeed` starts a background transcript prefetch for the current page plus the next page.

## Server (merged from .decisions-server.md)


- **Storage**: in-memory store (`lib/server/store.ts`) as a singleton on `globalThis`, so it survives dev HMR. JSON persistence to `.data/store.json` is opt-in with `STORE_PERSIST=1` (off by default, so Playwright runs start clean). No Postgres adapter; `db/schema.sql` documents the schema and its invariants (partial unique index for one unanswered quiz, correct_index range, study_completed <= study_required, distinct options via trigger).
- **Transactions**: every game mutation is synchronous, so a request's read-modify-write can't interleave with another request in one Node process. That makes credit decrement and idempotent grading race-free without locks.
- **Phase** is derived, not stored: `studyHall` flag, then an unanswered fun quiz (`quizOwed`), then an unanswered voluntary edu quiz (`study`), else `free`. A fun quiz past `expiresAt` is graded wrong the next time the session is touched (state/feed/start), which enters Study Hall.
- **Min watch**: required = max(0.7*duration, min(10, duration)). Unknown/0 duration means 10 s. The stored `duration_s` wins over the client value. Wall-clock check: watchedSeconds must be <= (now - time the video was served to this session) + 2 s. A video never served to the session gets 400 NotServed. "Watch again" resets the served time, so the re-watch is real.
- **Study Hall**: required = min(max(1, consecutiveFunFails), MAX_REQUIRED). A wrong answer on attempt 1 gives `watchAgain` (same reel, reshuffled options). A wrong answer on attempt 2 serves a different reel; it repeats the same reel only if it is the only playable one, and `completed` doesn't change. Any correct fun answer resets consecutiveFunFails.
- **Empty edu database**: a wrong fun answer records the fail but does NOT enter Study Hall (never deadlock). If every edu link becomes unplayable mid-visit, Study Hall exits with `next:'resume'`.
- **Escape** (`STUDY_HALL_ESCAPE=1`, off by default): after `MAX_REELS_PER_VISIT` (6) reels, a second wrong answer exits with `next:'resume', escaped:true`. Unplayable reels don't count toward it.
- **Voluntary study while a fun quiz is owed**: `/api/study/quiz/start` returns 409 QuizOwed (keeps "one unanswered quiz per session" and blocks credit farming). Watching reels is still allowed.
- **Credits**: checked before the min-watch check (per spec, a credit skips without needing the watch). A passed video (7-day pass) skips without using a credit.
- **Unplayable** marks are per session (so one browser's region/embedding error doesn't disable a link for everyone). Admin "verify" sets `embeddable` globally from oEmbed (200 yes / 401,403 no / 404 gone).
- **Custom sources**: `data/fun-links.json`, `data/edu-links.json`, `data/transcripts.json` (env overrides `FUN_LINKS_PATH`/`EDU_LINKS_PATH`/`TRANSCRIPTS_PATH`), parsed leniently (see data/README.md). A fun link without a quiz goes to `generateFunQuiz` in generated mode; otherwise it is **auto-passed** (no gate). An edu link without a valid quiz is loaded `active=false`. Duplicate (kind, video_id) entries upsert, and CSV import upserts too.
- **CSV**: header optional; correct_index is 0-based over the non-empty options; line numbers are the 1-based physical start line.
- **Rate limit**: 30 req / 10 s per session (`RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW_MS`), returns 429.
- **Fun feed mode**: generated only when both APIFY_TOKEN and ANTHROPIC_API_KEY are set and FUN_FEED_MODE isn't `curated`. Any generated-module error falls back to curated.

## Client (merged from .decisions-client.md)


- **One player per page.** `lib/client/useYouTubePlayer.ts` creates a single `YT.Player` and reuses it with `loadVideoById`/`cueVideoById`. Quiz and Study Hall panels hide the player container with `display:none` after calling `pauseVideo()` + `mute()`. The instance stays alive and nothing is ever drawn over it. The Play button, toasts, banners and Next/Prev all sit outside the player box.
- **Min-watch matches the server.** The client uses the same rule as `requiredWatchSeconds`: `max(0.7*d, min(10, d))`, or 10 s when the duration is unknown. The client check only exists to show the toast early; the server's 400 is the real gate.
- **watchedSeconds** is real elapsed time, counted every 250 ms only while the player state is PLAYING and the tab is visible. It is not the playback position, so seeking to the end doesn't count as watching.
- **The first video is cued, not played.** Nothing plays until the user clicks Play. After that, every load autoplays. A reel resumed after a reload also needs a click.
- **Study Hall runs inside `/`.** On page load the client calls `/api/state`; a pending quiz or `studyHall` phase takes priority over the feed. A 409 from any endpoint re-reads the state and moves into the right mode. To resume, the client finds `resumeAfterVideoId` in the feed it already has, or fetches the feed again and moves one past that Short.
- **`/study` refuses to run** while a fun quiz is owed or the session is in Study Hall, so credits can't be farmed. The server enforces this too.
- **When the answer timer runs out,** the client submits the currently selected option, or option 0 if none is selected. The server grades by `expiresAt`, so a late answer still counts as wrong.
- **Playwright tests** go in `tests/e2e/*.e2e.ts` so Vitest doesn't pick them up. `playwright.config.ts` falls back to the newest cached `chromium_headless_shell-*` when the bundled browser revision isn't installed (here 1248 is missing, so it uses 1234). The fake YT reports a 2 s duration, and failing video IDs can be set through `localStorage.__FAKE_YT_ERROR_IDS__` so the list survives a reload.
