# Shorts Gatekeeper Web

Shorts Gatekeeper is a vertical YouTube Shorts feed that is impractical on purpose. After each Short you get a one-question quiz about it, and you can't move on until you pass. A wrong or late answer sends you to **Study Hall**. There you watch educational reels, mostly math, from a curated database and answer their quizzes until you've earned your way back. The **server** enforces the gate: while a quiz is owed or Study Hall is in progress, the browser cannot get the next fun video ID.

## Setup

```bash
cd web
npm i
cp .env.example .env.local   # every variable is optional
npm run seed                 # load seed/edu-links.json + seed/fun-links.json into the store
npm run dev                  # http://localhost:3000
```

With no keys set, the app runs in **curated mode**. The fun feed comes from `seed/fun-links.json` and its hand-written quizzes. No Apify, no LLM and no network calls are made except the YouTube embeds.

`npm run seed:verify` checks that every seed video still exists and can be embedded. It also checks the shape of each quiz. Add `-- --write` to set `active: false` and add a comment on any rows that fail.

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `FUN_FEED_MODE` | `generated` if both keys below are set, otherwise `curated` | `generated` = discovery through Apify plus Claude-written quizzes. `curated` = fun links from the database. |
| `APIFY_TOKEN` | – | Optional. Needed only for generated mode (discovery and transcripts). |
| `ANTHROPIC_API_KEY` | – | Optional. Needed only for generated mode (quiz writing with `claude-opus-5-5`, low effort). |
| `FUN_SOURCES` | – | Generated mode discovery, e.g. `channel:MrBeast,keyword:funny shorts,hashtag:shorts`. |
| `NO_TRANSCRIPT_POLICY` | `metadata-then-pass` | Or `fail-closed`. Controls what happens when a Short has no transcript. |
| `DAILY_SPEND_CAP_USD`, `APIFY_DISCOVERY_MAX_USD`, `APIFY_TRANSCRIPT_USD_PER_ID`, `LLM_USD_PER_MTOK_IN/OUT` | 5, 0.25, 0.005, 5/25 | Spend caps and accounting rates. The LLM rates are placeholders; set them to the current price. |
| `YOUTUBE_API_KEY` | – | Optional. When set, `seed:verify` and the admin "verify" button use Data API `videos.list` (embeddable, duration ≤ 180 s, age restriction). Without it they fall back to oEmbed. |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `DATABASE_URL` | – | Reserved. **The MVP ships an in-memory store** (optionally saved to `.data/store.json` with `STORE_PERSIST=1`). `db/schema.sql` is the intended Postgres schema, but **the Supabase/Postgres adapter is not wired up yet**, so setting these does nothing today. Because the in-memory store lives in a single process, state is lost on restart and is not shared across serverless instances. |
| `ADMIN_PASSWORD` | – | Unlocks `/admin`. If it isn't set, admin is disabled. |
| `STUDY_HALL_ESCAPE` | `0` | `1` lets a user leave Study Hall after `MAX_REELS_PER_VISIT` (default 6) reels. This avoids endless loops when the database is tiny. |
| `MIN_WATCH_FRACTION` | `0.7` | Share of a Short you must watch before Next opens the quiz. The minimum is 10 s; if the duration is unknown, 10 s of play. |
| `ANSWER_TIMEOUT_SEC` | `30` | Time allowed to answer. An answer that arrives after `expiresAt` counts as wrong. |
| `MAX_REQUIRED` | `3` | Cap on how many reels Study Hall can require. |
| `CREDITS_PER_DAY` | `5` | Daily cap on earned Brain Credits. |
| `FUN_LINKS_PATH`, `EDU_LINKS_PATH`, `TRANSCRIPTS_PATH` | `data/*.json` | Optional custom lists, described below. |

## Customizing the videos

You can drop your own lists into `web/data/` or point the env vars somewhere else:

- `data/fun-links.json` (`FUN_LINKS_PATH`) and `data/edu-links.json` (`EDU_LINKS_PATH`). The format is lenient. Either:
  - an array of URL strings (`watch?v=`, `/shorts/` and `youtu.be` forms, or bare 11-character IDs), or
  - an array of objects with `url` or `video_id`, plus optional quiz fields matching the seed format: `title`, `topic`, `difficulty`, `question`, `options`, `correct_index`, `explanation`, `active`.
- Edu links **need** a quiz (`question`, `options`, `correct_index`, `explanation`). Without one they can't be used in Study Hall.
- Fun links without a quiz can still be used in generated mode, where the quiz is written from the transcript.
- `data/transcripts.json` (`TRANSCRIPTS_PATH`) holds pre-extracted transcripts, either as `{ "<videoId>": "text…" }` or as an array of `{ videoId, text, lang?, isAutoGenerated? }`. Cached transcripts are used before any call to Apify.

Run `npm run seed:verify` after editing. It checks the `data/*-links.json` files too, including plain URL strings. Plain-string rows are only reported, never rewritten.

## CSV import (`/admin`)

```
kind,video_id_or_url,title,topic,difficulty,question,option1,option2,option3,option4,correct_index,explanation
edu,https://www.youtube.com/shorts/v1P1X-r0vPQ,Ramanujan Nested Radicals,math,2,What does the nested radical equal?,2,3,pi,,1,It equals 3.
```

- The header row is optional. It is detected if the first row's first cell is `kind`.
- `correct_index` is **0-based** and counts only the non-empty options.
- Each row needs 2–4 distinct, non-empty options and a non-empty explanation. The ID is taken from watch, shorts and youtu.be URLs or from a bare ID.
- Bad rows are reported with their line numbers. The rest are imported.

## Rules

**Fun feed.** Watch at least `MIN_WATCH_FRACTION` of a Short, then press Next or Prev. The player is paused, muted and hidden, and the quiz takes its place. Nothing is ever drawn over the player. A correct answer moves you on. A wrong answer or an expired timer sends you to Study Hall. There is no time-based lockout anywhere.

**Study Hall.**
- Required reels = `min(consecutive fun fails, MAX_REQUIRED)`: 1 on the first fail, 2 on the second in a row, then 3.
- Each reel has a pre-written quiz. A correct answer counts toward the requirement.
- A wrong answer shows the explanation and offers "Watch again" with the options reshuffled. A second wrong answer moves you to a different reel, and nothing is counted.
- Reels are picked least-recently-seen first. Unplayable reels are skipped and never count.
- Reloading or opening a new tab picks up the same reel and attempt.
- When you finish, you return to the fun feed at the Short after the one you failed.
- Passing a fun quiz after Study Hall resets the fail streak.

**Brain Credits.**
- Pass a reel in the voluntary `/study` tab to earn one credit.
- At most `CREDITS_PER_DAY` per day, and each link earns credit once per 7 days per session.
- Credits **cannot be earned while a quiz is owed or you are in Study Hall**.
- Each credit auto-skips one fun quiz. The skip is on by default and can be turned off in settings.
- Credits are decremented atomically.

## Generated-mode costs (estimate)

These are rough numbers. Check current Apify actor pricing and Anthropic pricing before you depend on them.

- **Discovery (Apify):** one actor run per source per refresh (30-minute cache). Each run is capped by `maxTotalChargeUsd` (default $0.25). Pay-per-result scrapers are usually somewhere around $0.5–$5 per 1000 results, so expect **about $1–5 per 1000 Shorts discovered**.
- **Transcripts (Apify `devsef~youtube-transcript-scraper`):** batches of up to 200 IDs. This is accounted at `APIFY_TRANSCRIPT_USD_PER_ID` (default $0.005), so **up to about $5 per 1000 Shorts**.
- **Quizzes (Claude `claude-opus-5-5`, low effort, `max_tokens` 1024):** about 1–2k input tokens (transcript + prompt) and up to about 1k output tokens per Short. At the placeholder rates of $5/MTok in and $25/MTok out, that is roughly $0.01–0.035 per quiz, or **about $10–35 per 1000 Shorts**. Retries can add up to 2×.
- **Total:** roughly **$15–45 per 1000 fun Shorts quizzed**, before caching. `DAILY_SPEND_CAP_USD` (default $5) is a hard stop. Over the cap, the app falls back to the no-transcript policy.

Curated mode and Study Hall cost $0.

## Accepted bypasses

This is a self-control toy, not DRM. These bypasses are known and accepted:

- **Anonymous users can clear cookies or use a private window** to get a fresh session with no quiz owed and no Study Hall. Signing in would tie the state to a user, but magic-link auth needs the Supabase adapter, which isn't wired yet.
- **Going to youtube.com directly.** We can't, and shouldn't, stop that.
- Restarting the server wipes the in-memory store.

## Privacy

- **Fun feed (generated mode only):** video IDs, titles and transcripts are sent to **Apify** (scraping) and **Anthropic** (quiz writing).
- **Educational links and their quizzes never leave your server.** They are hand-written in the database.
- No personal data is sent to any third party. Sessions are random IDs stored in a cookie.
- YouTube's embedded player sets its own cookies under YouTube's privacy policy.

## YouTube compliance notes

- **No overlays:** quiz and Study Hall panels replace the player. The player is paused, muted and hidden, and the panel is drawn in its place. Nothing ever covers the iframe.
- **One player:** at most one player at a time, and nothing reacts to hover or touch on the player.
- YouTube branding and the "watch on YouTube" link are left intact. The minimum player size is respected.
- **No downloads:** videos are never downloaded, cached or re-hosted. Only IDs and metadata are stored.
- If YouTube reports an embed as unplayable (errors 100/101/150), the app skips it.

## Testing

```bash
npm test            # Vitest unit tests (grading, Study Hall state machine, credits, CSV, ID extraction, fallback ladder, spend)
npm run test:e2e    # Playwright, FUN_FEED_MODE=curated with a fake YT.Player and mocked Apify/Anthropic/Data API
npm run seed:verify # live check of the seed IDs (oEmbed or Data API)
```

For a manual pass against real embeds, see `docs/live-check.md`.

**Verification status:** all 24 edu and 8 fun seed IDs returned HTTP 200 from YouTube oEmbed on 2026-10-16, so they exist and allow embedding. They have **not** been checked with the Data API (no key was available), so durations and age restrictions are unconfirmed. Many quizzes were written from the video's title and channel context rather than from watching the video. Those rows are marked `"comment": "quiz written from title; review"` and should be checked by a human.
